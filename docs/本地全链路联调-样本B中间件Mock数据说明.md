### 1.1 78 种污染字符的构成

这是评审报告 P1-3 关心的那一项，实测拆开来看：

| Unicode 区块 | 种类 | 次数 | 谁来处理 |
|---|---|---|---|
| 康熙部首 U+2F00–2FDF | 65 | 739 | **NFKC 自动分解**，无需映射表 |
| CJK 部首补充 U+2E80–2EFF | 13 | 156 | 必须靠 `RadicalNormalizeMap` 显式映射 |
| 私用区 PUA | 0 | 0 | —— |

13 种 CJK 部首补充区字符**全部已收录**在现有 20 条映射里：

```
⻅→见(75)  ⻮→齿(14)  ⻛→风(12)  ⻣→骨(12)  ⻝→食(12)  ⻓→长(12)  ⻔→门(6)
⻩→黄(4)   ⻙→韦(3)   ⻆→角(2)   ⻰→龙(2)   ⻬→齐(1)   ⻘→青(1)
```

**结论：规范化后残留污染 = 0**（已由联调实跑确认）。评审报告 §8.2-1 的验收断言成立。

## 2. 菜单 B —— 12 道菜

样本 B 用一套独立菜单。**不是为了换而换**：菜单 A 的 18 道已经覆盖了 13 个过敏组和主料规则的边界，
菜单 B 专门补 A **没走到**的三类分支。

> 菜单由 Spring 属性 `local-chain.dish-menu` 选择（`A` / `B`），
> 配错值直接失败不静默回退——回退会让「配错了」表现成「预期表对不上」，排障时找错方向。

### 2.2 每道菜补的是哪个分支

| 覆盖目标 | 菜品 | 说明 |
|---|---|---|
| **过敏例外规则真正生效**（菜单 A 里一次都没成立过） | 1101、1107 | 菜名被 REVIEWED 例外豁免，**且食材里也没有触发词**——两个条件同时满足才看得到豁免效果 |
| 例外只作用于菜名、不作用于食材 | 1108 | 菜名「蟹柳」豁免 SHRIMP_CRAB，真正的风险线索落在食材「鱼糜」上转入 FISH，正是词表注释描述的那条路径 |
| 别名表其余四条 | 1103、1104、1105 | 鲜猪肝→猪肝、嫩豆腐→南豆腐、老豆腐→北豆腐（菜单 A 只覆盖了 猪瘦肉→瘦猪肉） |
| **「仅展示食材」不得触发推荐** | 1106、1111 | 南瓜只在 POTASSIUM 的展示清单里且该维度可推荐清单为空；芥蓝只在 CALCIUM 的展示清单里 |
| 词表的具体性（不靠例外补救） | 1102 | MILK 词表用「牛奶/酸奶/奶酪/淡奶/奶盖/奶粉」等具体词，**没有裸「奶」**，所以椰奶天然不会被误拦 |
| 一道菜触发两个过敏组 | 1104、1109、1110 | EGG+SOY / FISH+WHEAT / WHEAT+SESAME |
| 过敏兜底不看重量 | 1110、1112 | 芝麻酱仅 25 克不是主料仍命中；1112 全部重量未知仍命中 FISH |

> **1102 是一次预期被推翻的记录。** 设计这道菜时我以为它会命中 MILK：
> `AllergenExceptions` 里有四条 `MILK/"奶"` 的规则（奶白菜、椰奶、豆奶、杏仁奶），
> 它们都是 `REJECTED` 状态、不生效，所以我预期「椰奶」会被裸「奶」拦下。
> 实跑不命中——查词表才发现 MILK 组**根本没有裸「奶」这个词条**。
> 那四条规则是给一个不存在的匹配词准备的、且已被拒绝，属于「保留在原位置防止未经复核重新加入」
> 的正常留痕，不是缺陷。**词表用具体词而不是靠例外去补救宽泛词，这个方向是对的。**

### 3.1 LLM-B 打标规模

12 道菜 × 22 个维度 = **264 个三元组**，每维度一批（批上限 40），共 **22 次 LLM-B 调用**。
实跑落库 264 行，作废批次 0。

## 4. 怎么跑

```bash
export JAVA_HOME=$(/usr/libexec/java_home -v 1.8)

# 样本 B 的契约桩全链路（走真实 HTTP）
mvn -P local-chain test -Dtest=StubbedSampleBRunTest

# 只看解析路由诊断
mvn -P local-chain test -Dtest='StubbedSampleBRunTest#parseRoutingDiagnosticShouldBeExplicit'
```

| 文件 | 作用 |
|---|---|
| `LocalChainMockDishes.java` | 菜单 A（18 道）与菜单 B（12 道），单一真源 |
| `AbstractStubbedChainTest.java` | 两份样本共用的桩链路流程与断言 |
| `StubbedSampleARunTest.java` | 样本 A + 菜单 A |
| `StubbedSampleBRunTest.java` | 样本 B + 菜单 B |

流程与断言完全共用，样本子类只提供报告路径与预期页数——两份样本的用例各写一遍必然分叉。

## 5. 变更纪律

- 改动 §2.1 的菜品数据 → §3 的预期表必须同步重算（`tagHash` 会变，会触发全量重打标）；
- 本文件与代码不一致时，**以本文件为准并立即改代码**；
- 菜单 B 只在 `local-chain.dish-menu=B` 时生效，且整套 Mock 只存在于 `src/test`。
