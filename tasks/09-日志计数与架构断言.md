# 开发任务 09：日志白名单、生产计数清单与架构断言

> 判据优先级：`AGENTS.md` > 本任务文件 > `AI体检报告分析-开发方案V1.md` > `AI体检报告分析-精简设计方案V1.md` > `体检报告分析需求.md`
> 与更高优先级的安全、持久化、公开接口或医疗规则冲突时停止为 BLOCKED，不得自行选规则。

> 覆盖开发方案 §9.2 / §9.3 / §11.1（ArchUnit）/ §11.5（上线前必跑）。

## 1. 目标

补齐全工程的日志红线、生产计数清单、架构断言与上线前必跑测试集。
**本任务只加断言与计数，不改业务逻辑。**

## 2. 范围

- 要修改的模块：全工程
- 允许修改的接口：新增计数器与 ArchUnit 测试
- 允许修改的数据库表/字段：无
- 允许修改的 Prompt/Schema/常量：无

## 3. 功能要求

1. **日志白名单**（§9.2）：绝不记录报告原文、证据文本、OCR 文本、姓名、原始过敏或医嘱文本、
   健康数据、凭证、模型完整请求响应、**`origin_name`**。
   `taskId`/`userId` 可用于关联，但**不得与上述内容出现在同一条日志事件中**。
2. **生产计数清单**（§9.3）**就是全部**，不在其上的一律不实现：
   `schemaMissCount`、`evidenceMissCount`、`ocrFuzzyMatchCount`、`allergenSuspectMissCount`、
   `allergenPositiveUncoveredCount`、`allergenUnknownCount`、`adviceOtherCount`、`sectionRefMissCount`、
   `sectionUnknownCount`、`highRiskSuppressedCount`、`glyphLevelPdfCount`、`residualNonStandardCount`、
   `statusJudgedByModelCount`。
   **三个已下线的计数不得实现**：`statusConflictCount` / `foodBorneConflictCount` / `normalAdmitSuspectCount`。
3. ArchUnit 断言：**R1**（三张语义词表无生产引用）、**R6**（`parse` 包无 `PDFTextStripper`、无坐标聚类）、
   **R57**（LLM-A 链路不依赖 `DifyClient`）、两个线程池分离、上传图片路径禁 `ImageIO.read`。
4. 建立 §11.5 的「上线前必跑」测试集（独立 profile / tag）：**R65p**、**R66g**、**R66b**、**R66h**，
   并要求**跑过的结论留档**（分配量基线、实测峰值、OCR 的 EXIF 结论）——**没有留档等于没跑过**。

## 4. 验收条件

- [ ] 安全与日志：**R49** —— 全流程日志捕获，不含报告原文/姓名/OCR 文本/健康数据/`origin_name`
- [ ] 安全与日志：**R48** —— Redis 结果不含姓名、性别、完整 OCR 文本
- [ ] 边界场景：**R1/R6/R57** ArchUnit 全部通过
- [ ] 边界场景：**R53** —— `statusJudgedByModelCount` 只数 `true` 的条数
- [ ] 边界场景：清单外的计数在生产代码中不存在（三个已下线计数逐一断言缺席）
- [ ] 失败场景：故意加一处 `ConclusionLabelWords` 引用 → R1 失败（**证明断言有效**）
- [ ] 幂等/并发场景：不适用
- [ ] Java 8 全量构建通过：是

## 5. 不做什么

- 本任务不包含：任何业务逻辑改动
- 不允许新增：清单外的任何计数；任何为「只告警」而扫词表的逻辑
- 不允许改变的既有行为：无

## 6. 外部依赖与已确认决定

- 外部接口/凭证/测试数据：无
- 产品已确认决定：三张语义词表已整体下线，移入离线评测
- 医疗审核结论：不适用

## 7. 交付物

- 代码：计数器、ArchUnit 测试、上线前必跑 profile
- 测试：R1、R6、R48、R49、R53、R57 + 断言自身有效性
- DDL/Prompt/Schema/文档同步：无
