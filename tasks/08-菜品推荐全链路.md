## 3. 功能要求

### A. 离线打标任务与 `tagHash`（原 22）

1. **打标与清理是同一个 `@XxlJob` Handler 的两步**，`bizDate` **只在 `execute()` 里取一次**逐层传下去。
   两个独立 Handler 拿不到同一个 `bizDate`，跨零点会分叉。**`dish` 包内只有一个 Handler**。
2. `tagHash = sha256(tagRuleVersion|promptVersion|modelVersion|normalize(菜名)|食材串)`；
   食材按 `normalize(name)` **字典序排序**、`weightG` 统一克并四舍五入 1 位、**未知编码为 `null` 不是 `0`**。
   **不排序会让外部返回顺序一变就触发全量无意义重打。**
3. LLM-B 三态 `REJECT` / `UNKNOWN` / `NEUTRAL`；
   **覆盖与互斥断言由 Java 在写库前做**：`neutralDishIds ∪ unknownDishIds ∪ hitList` 精确等于本批输入
   且**三者两两不相交**；少/多/重复 → **整批作废，不写库、不重试**，
   **遗漏的菜绝不静默补成 `NEUTRAL` 也不补成 `UNKNOWN`**。
4. 逐条校验：`matchedIngredients ⊆ 该菜食材表`，全对不上 → **降 `UNKNOWN`**
   （不是 `NEUTRAL`：证据不成立 ≠ 确认不含）。
   **这里没有「未返回的菜 → TAG_MISSING」**——覆盖不完整在写库前就整批作废了。
5. 缓存与回源（§8.3）：Key 按维度组织 + `bizDate` 每日重建；
   **Redis 未命中必须回源查 `ct_dish_tag`**——没有它，预热失败当天推荐列表整个空掉。
   仍查不到 → `TAG_MISSING`（**不是 `NEUTRAL`**）。
6. 清理：`last_seen_date < DATE_SUB(:bizDate, INTERVAL 30 DAY)`，分批 `LIMIT 5000`，
   **必须在打标之后跑**（先删后打会误删当天要用的行）。

### B. 菜品查询、主料推导与营养维度（原 23）

7. **`ct_dish_ingredient` 里没有调味料**（已确认）。
   **全案禁止「食材表里没有 X 所以判 NEUTRAL」的推理**——它只能推出「主料配料里没有 X」。
   这一条要写进 Java 兜底的注释里。
8. 营养补充**纯 Java 确定性交集**：`intersect(mainIngredients(dish), recommendIngredients)`，
   空则 `NEUTRAL` 否则 `RECOMMEND`。**该维度永远不会 `TAG_MISSING` 也不会 `UNKNOWN`**。
9. 食材名对不上用 `IngredientAliasWords` 兜一层，未命中按不匹配（方向保守，只会少推荐）。
10. 主料推导（§7.5.4）：**没有「排除调味料」这一步、没有 `SEASONING` 常量**——食材表本来就不含调味料。
    规则一 占比 ≥ `MAIN_RATIO(0.25)`；规则二 前 2 名且 ≥ `TOP_N_MIN_RATIO(0.15)`；两条取并集；
    都不满足取最重的一个。**全部无重量 → 返回空集**（该菜营养维度全 `NEUTRAL`）。

### C. 模块四 五态裁决与展示（原 24）

11. **过敏 Java 关键词兜底**：匹配范围菜名 + 全部食材名，**无重量阈值、微量即命中**，
    与模型结果**取并集**，**模型不可推翻**。
    **食材表没调味料后这一层实际只剩「菜名」一条通路**——「红烧肉里的酱油」拦不到。
12. **枚举外过敏原**（`OTHER` 且 `isFoodBorne=true`）：字面匹配菜名 + 食材名；
    `isFoodBorne=false` 的**完全不进本节任何逻辑**（艾蒿↔青团的艾草会误杀）。
13. **五态**：`TAG_MISSING` / `UNKNOWN` / `NEUTRAL` / `RECOMMEND` / `REJECT`。
    `TAG_MISSING` 与 `UNKNOWN` **裁决同结果但必须是两个值**——前者是预热问题，后者是数据/提示词问题。
14. **完整性门槛**：可产生 REJECT 的维度里任一为 `TAG_MISSING` 或 `UNKNOWN` →
    **不进推荐列表，也不进不推荐列表**（不展示）。
    **不放进不推荐列表**：我们并不知道它违规，那是错误指控。
15. **合并裁决**（§7.5.8）按五行顺序；**过敏拒绝的菜不下发任何正面标签**，灰色附注也不行。
16. 排序与截断：拼音首字母（TinyPinyin，**实时算不落库**），非汉字排汉字后，各取前 3。
    **截断必须在全部维度合并裁决之后**——先取 3 再判过敏会把该拦的留下、该推的丢掉。
17. 推荐理由由 Java 拼接，引号引用原文；三种空态文案按 §7.5.9。
18. `suppressDishRecommend=true` 时**整个模块不输出**。

## 5. 不做什么

- 本任务不包含：日志计数清单与架构断言（任务 09）
- 不允许新增：任何在线调用 LLM-B 的路径（在线调用次数必须为 0）；`SEASONING` 常量；
  任何写菜品库的操作；任何让模型推翻 Java 兜底的路径；任何把 `TAG_MISSING`/`UNKNOWN` 当 `NEUTRAL` 的处理
- 不允许改变的既有行为：`tagHash` 公式保持版本号驱动（摘要方案已否决）；
  阈值 0.25 / 0.15 是**待校准值**，不得自行改动
