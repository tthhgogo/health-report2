## 3. 功能要求

### A. 排序总则（原 19 §7.1）

1. `assemble.sort.DisplayOrder` 是**全案排序的唯一实现**，**禁止在模块里另写比较器**。
   分组 `fileIndex → groupOrder`；组内 `groupOrder → page → orderInSection`；
   条目 `groupOrder → page → sourceOrder`。
2. **三条硬约束**：顺序字段一律由 LLM-A 给；批内序号跨批会撞，每条排序键必须先用 `page` 收敛；
   `sourceOrder` 作用域是「章节内、批内」所以前面必须先有 `groupOrder`；
   **任何排序键都不得使用 `segmentId` 里的 `seq`**（那是解析器产出顺序）。
3. `page` 契约里没有，Java 从 `segmentId` 算：`item.page = min{page(segmentId)}`、
   `group.page = min{item.page}`。**取 `min`**——跨页续表属于它开始的那一页。
4. `groupKey = fileIndex + "-" + 有效 sectionSegmentId`，按 `sectionRelation` 四态取值（§7.1 表）；
   **Java 只在 `CONTINUATION` 时继承**，`UNSECTIONED`/`UNKNOWN` 单独成组。
   文件第一批就报 `CONTINUATION` → 按 `UNKNOWN` 处理，**不向前跨文件继承**。

### B. 模块一 健康指标（原 19 §7.2）

5. 五个卡片字段；`refRange` 没写时展示「报告未提供」，**禁止填充通用参考值**。
   **`status` 由 LLM-A 给，Java 在线不做任何校验**。
   展示规则：**颜色跟判定，文字跟原文**——标签文字是 `conclusionText` 原文，**不写「异常」二字**。
6. 总览条：`reportOverview` 非空且过了数字校验则展示报告数字并标注「（报告原文）」，
   否则用本模块卡片计算。**不加任何差值说明文案**。
7. 空态：「本次报告未提取到带明确结论的指标项」，**保留总览条位置展示 0，不隐藏模块**。

### C. 模块二 健康问题（原 20 §7.3）

8. 三类来源的准入**统一用 LLM-A 的 `includeInHealthProblems`**，
   **不得由 `status != NORMAL` 派生**——准入是语义判断，不是 `status` 的机械函数。
9. `INDICATOR_TEXTUAL` **不带 `indicatorId`**：无数值结论根本不会生成指标卡片，没有跳转目标。
   前端只对 `INDICATOR_NUMERIC` 显示跳转按钮。
10. `displayName`：`problemName` 非 null 用它；为 null 时 Java 拼 `name + " " + conclusionText`
    ——**两段都是报告原文，只做字符串连接**。
    **绝不拼「归一化结论词」**：报告写「↑」就是「甘油三酯 ↑」，**不得翻译成「甘油三酯偏高」**。
11. `displayNameGenerated` 标记是否走了拼接分支。
12. `sourceLabel` 的章节名取 §7.1 的 `displayName`，**不写死「总检结论」**。
13. 排序调 `DisplayOrder`；**不做严重程度分级、不做风险排序**。空态与底部声明按 §7.3 原文。

### D. 模块三 饮食建议与高危安全闸（原 21 §7.4）

14. **三条硬约束靠结构保证**：本模块的**输入只有 `enumKey` + `rawText`**，
    **结构上看不到指标数据**——不是靠提示词嘱咐。
15. **来源标注完全由字段拼出，Java 不做任何推断**：
    章节展示名 ← `sectionIndex` → §7.1 的 `displayName`；
    「第N条」← `itemNo` 非 null 时用它，**为 null 时不写条号，不拿 `sourceOrder` 顶替**
    （那个数字报告上没印，显示出来就是编造）；原文 ← `blockRefs` 展开后取整段 `rawText`。
16. **高危表述安全闸**：对 `rawText` 扫黑名单（低蛋白/限钾/低碘/妊娠…），
    命中 → 打 `structuredOutputSuppressed = true` 走 `OTHER` 路径，记 `highRiskSuppressedCount`。
    **不覆写 `enumKey`** —— 它是 LLM-A 的归一化结论，改它就是替模型下另一个结论；
    原值原样保留仅用于排障。这道闸**只会让系统少输出内容**。
17. `OTHER`（含被抑制的）：照常展示原文与来源、**不加任何说明文字**、
    不生成食材清单、不参与菜品匹配、不进入打标维度，记 `adviceOtherCount`。
18. 三个分区的空态文案 + 底部声明按 §7.4 原文；**全模块不出现任何提示、说明或警示文字**。
